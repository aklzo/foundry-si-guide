## 概要

トレーシング・評価・モニタリングを統合した観測基盤を扱う。領域別のステータスは混在しており、[Feature readiness at GA](https://learn.microsoft.com/en-us/azure/foundry/concepts/general-availability)(2026-08-14 版。updated_at 2026-09-23 の版を 2026-09-26 に再確認、本章の該当行に変化なし)の記載が最も体系的:

- Tracing(Trace Replay 含む): **prompt / hosted エージェントは GA、workflow / 外部エージェントはプレビュー**
- Tracing VNet: プレビュー
- トレース→評価データセット変換: プレビュー
- Evaluations: **GA**(一部評価器・機能はプレビュー)
- Monitoring: **プレビュー**
- Red teaming: **GA**
- Optimization (cluster analysis): プレビュー
- Agents — traces in agent builder: プレビュー
- Operate > Compliance: プレビュー
- (表外・2026-09-26 追記)**Insights in Foundry: パブリックプレビュー**(2026-09-24 発表。GA 一覧表にはまだ行がない)
- (表外・2026-10-06 追記)**トレースの機微コンテンツ保護(`AppGenAIContent` 専用テーブル): パブリックプレビュー**(GA 一覧表に行なし。下表)。**GA 一覧表は 2026-10-06 時点でも updated_at 2026-09-23 のまま**で、`azure-ai-projects` 2.8.0(2026-10-02)が GA と書いた data generation / evaluator lifecycle(Rubric 生成)/ Agent Optimization の各 API も表上はプレビュー(Convert traces to evaluation datasets = Preview、Agent optimizer = Limited preview)→ 該当行で両論併記
- (表外・2026-10-14 追記)**Learn の個別ページから「(preview)」が外れた機能が増えた** — rubric-evaluators(h1「Rubric evaluators」ms.date 2026-09-30)・traces-to-dataset(「Convert agent traces into evaluation datasets」10-08)・evaluation-dataset-synthetic(「Generate a synthetic evaluation dataset」10-08)・cloud-evaluation-conversations / cloud-evaluation-simulate-conversations(10-07)・agent-optimizer-overview(「What is the agent optimizer?」03 の担当行)。いずれもプレビュー定型文もないが **GA の明記もない**。一方 **GA 一覧表は 2026-10-14 時点でも updated_at 2026-09-23 のまま**(Convert traces to evaluation datasets = Preview / Agent optimizer = Limited preview)で、built-in-evaluators の見出しも「Rubric evaluators (preview)」のまま。→ **SDK(2.8.0)= GA / Learn の機能ページ = ラベルなし / GA 一覧表 = Preview の 3 者併記**。本書は GA 一覧表を正とし**プレビュー扱いを維持**する(SLA・サポートを論点にする提案では GA 一覧表の更新を待つ)。トレース評価(deployed-conversations / deployed-interactions)・合成クエリ生成(`*_preview` データソース)・管理者接続モデルは Learn でも preview のまま

## 補足ノート

**1. Trace Replay のステータス揺れ(重要・2026-09-26 も継続)**

**2. 評価 SDK の世代交代**
新 Foundry の評価ドキュメントは全面的に **`azure-ai-projects`(>=2.2.0)+ OpenAI 互換 evals API**(`client.evals.create` / `builtin.*` 評価器名)ベースに書き換えられた。`azure-ai-evaluation`(ローカル評価)は stable 1.18.7(PyPI 2026-09-25)まで更新が続き廃止告知はないが、ドキュメントは foundry-classic 配下(hub-based プロジェクト向け)に隔離され、見出しにも「(preview)」が付く。正式な移行アナウンス文書は未確認(2026-09-26 再確認)。2026-08 にはクラウド評価ドキュメントがハブ(cloud-evaluation)+ 7 本(datasets / targets / deployed-interactions / conversations / synthetic-data / results / admin-connected-models)+ データセット概念 2 本(evaluation-datasets / evaluation-dataset-schema)に再編され、全ページで Python と JavaScript/TypeScript(`@azure/ai-projects`)・cURL を併記。機能ごとに要求版が異なる(ハブ >=2.2.0、エージェント評価・トレース→データセット >=2.4.0、合成データセット生成 >=2.5.0、Insights >=2.6.1)。**(2026-09-26 追記)** 2.4.0 で評価器生成・データセット生成・最適化ジョブの作成が LRO(`begin_*` ポーラー)に変わり、2.5.0 で Python 3.10 以上・`openai>=3.0.0` が必須、2.7.0 で beta のデータ生成オプションから `max_samples` 引数が削除された(PyPI 変更履歴・7・8 月号ブログ 2026-09-09)。ドキュメントのコード例が最新 SDK に追いついていない箇所があるため、評価パイプラインの SDK 更新時は「ジョブ投入〜完了」まで通しで検証する。**(2026-10-14 追記)** 10-07〜10-08 版で要求版が割れた: evaluate-agent・traces→dataset・合成データセット生成は **>=2.8.0**(data generation / evaluator 生成は `project_client.datasets` / `project_client.evaluators` の beta 外に移動)、一方 deployed-conversations(トレース評価)は preview ワークフロー用に **==2.7.0 に固定**、合成シード(Simulation seed)は 2.8.0 では作れずポータル必須。**同じプロジェクトで「2.8.0 の GA 型」と「2.7.0 固定の preview 手順」が混在しうる**ので、評価パイプラインはワークフローごとに版を分けて固定するか、SDK リポジトリのサンプル(2.8.0 で GA データソースに移行済み)を正とする。`azure-ai-evaluation` は 1.18.8(2026-10-09、バグ修正のみ)。

**3. 継続的評価の位置づけ(2026-09-07 訂正)**
Monitor 設定パネル(how-to-monitor-agents-dashboard 2026-08-08 版)は「Recurring evaluations (preview)」「Red team scans (preview)」「Alerts (preview)」の 3 項目構成になり、継続的評価(Continuous)はスケジュール評価(Scheduled)と並ぶ「Recurring evaluations」の一種として **preview に包含**された(旧版で Continuous evaluation だけ preview 表記がなかった状態は解消)。ダッシュボード表示自体も preview、GA 一覧(2026-08-14 版)でも Monitoring 領域全体がプレビュー。なお Microsoft のブログ(Tech Community 2026-03-16「Generally Available: Evaluations, Monitoring, and Tracing」)は Monitoring を GA と表現しているが、GA 一覧表が最終権威につき本書はプレビュー扱い。本番採用判断時は「継続的評価を含む監視系は全体がプレビュー」として扱う。

**4. サーフェス全般の傾向(2026-09-26 更新)**
観測性・評価領域の手順書は「Foundry(新)ポータル + Python SDK(`azure-ai-projects`)」が主線で、2026-08 の再編後は JavaScript/TypeScript(`@azure/ai-projects`)と REST(cURL)を全ページで併記。C#/.NET は 2026-09-07 時点では継続的評価ページのみだったが、2026-09-26 時点ではクラウド評価のハブと各 SDK ページ・トレース設定にも C# タブがある。REST の api-version は `2025-11-15-preview` が主だが、合成データ生成ページは `v1` を使用(混在)。**Azure CLI(`az`)の手順は Entra トレース取り込みのロール割当(`az role assignment create`)のみ**(2026-07-30 版の「どのページにも記載なし」から更新)。評価の CLI サーフェスは Azure CLI ではなく **azd 拡張(`azd ai agent eval`、プレビュー)** が担う。Insights は Foundry MCP Server / Microsoft Foundry Skill から読み取れる(2026-09-26 追記)。

**5. Purview / Defender 連携の設計上の注意(2026-09-07 追記)**
Purview 連携の有効化は Foundry の Operate > Compliance(Foundry Account Owner)が現行手順で、Defender for Cloud 側のトグルは「deprecated」明記(ai-onboarding 2026-07-29 版)。Purview 連携は**ネットワーク分離未対応**(how-to-manage-compliance-security 2026-05-15 版)、Data Security Policies は Entra ユーザーコンテキスト付きの `/chat/completions` 呼び出しにのみ適用、PAYG 未設定なら Audit のみ。Foundry agents のデータが対象に含まれるかは記載が揺れる(control plane ページ「applications and agents」 vs Defender ページ「Foundry agents のデータは含まれない」)ため、エージェント案件では要確認。Defender for Cloud の AI threat protection は GA だが 30 日試用に 750 億トークンの上限があり、Foundry Models 経由のテキストトークンのみが対象。
